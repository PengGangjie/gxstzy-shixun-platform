## 1. 五类使用群体

| 角色码 | 中文 | 典型人选 | 数据范围 |
|--------|------|----------|----------|
| `jw_admin` | 教务处管理员 | 实训科、教务处分管 | **全校**；用户与角色指派 |
| `college_admin` | 学院管理员 | 学院分管领导、实训/安全联络人 | **本学院**；可指派本院实验员/教师/学生（不可造教务处管理员） |
| `lab_tech` | 实验员 | 实训室管理员、实验技术人员 | **本学院**；优先绑定负责房间（`lab_rooms`）；可维护一室一表/本室台账（写能力 Phase 2） |
| `teacher` | 教师 | 任课教师 | **本学院**只读为主；制度、虚拟仿真、未来模块、本学院台账检索；无迎检全量、无用户管理 |
| `student` | 学生 | 在校生 | **个人学习向**：制度摘要、虚拟仿真、安全准入/责任书入口（建设中）；无台账明细、无一室一表全库、无迎检、无管理 |

库字段（沿用并扩展）：

- `users.role`：上表五码之一  
- `users.college`：学院全称（`jw_admin` 可空）  
- `users.lab_rooms`（新增，TEXT JSON 数组，可空）：实验员负责房间号列表，如 `["西6-6205","…"]`  

登录 `upsert`：新用户默认 **`student`**（最窄）；**永不覆盖**已人工设定的 role / college / lab_rooms。

学院取值（与台账一致）：  
林学院、经贸学院、园林学院、设计学院、旅游学院、汽信学院、建工学院、环保学院、智造学院、通识学院。

> 五类**不是简单高低梯子**：实验员与教师同属学院侧、能力正交。代码用 **能力集合（capabilities）**，不要用单一 `ROLE_RANK >= n`。

## 4. 指派规则（防越权）

| 操作者 | 可指派角色 | 可设学院 / 房间 |
|--------|------------|-----------------|
| `jw_admin` | 全部五类 | 任意学院；任意房间列表 |
| `college_admin` | `lab_tech` / `teacher` / `student` | 仅本院；房间须属本院台账 |
| 其余 | 不可指派 | — |

新账号未设学院时：`student` 可进学习向模块；`teacher`/`lab_tech`/`college_admin` 缺学院则仅首页+提示「请联系教务处/学院管理员完善档案」。

引导管理员：环境变量 `ADMIN_EMAILS`（逗号分隔）→ 首次登录升为 `jw_admin`。

```sql
-- 应急升权
UPDATE users SET role = 'jw_admin', college = NULL, updated_at = datetime('now')
WHERE email = '你的邮箱@...';
```

## 5. 路径与 API（实现要点）

### 5.1 公开

仅：`/health`、`/sign-in`、`/callback`、`/sign-out`。  
敏感 `.json` **不得**未登录直链；已登录也按 capability 经 API 下发裁剪结果。

### 5.2 关键接口（PR 顺序）

| 接口 | 所需能力 | 范围 |
|------|----------|------|
| `GET /api/me` | 已登录 | 返回 role、college、lab_rooms、capabilities |
| `GET /api/admin/users` | `users.manage_all` 或 `users.manage_college` | 后者仅本院 |
| `POST /api/admin/users/{sub}/role` | 同上 + 指派规则 | 写 audit_log |
| `GET /api/ledger/rooms` | `ledger.read` | 按 data_scope 过滤 |
| `GET /api/yishi/...` | `yishi.read` | 同上 |
| `GET /api/inspect/...` | `inspect.read` | 教务处全量 / 学院管理员本院 |

## 7. 验收标准

1. 未登录 → 登录；敏感 JSON 直链失败  
2. 新用户默认 `student`：可见虚拟仿真等，不可开台账/迎检/管理  
3. `teacher` + 园林：台账仅园林只读；迎检 403  
4. `lab_tech` + 房间列表：明细不超出本院（MVP），Phase 2 不超出房间  
5. `college_admin` 不能把他人升为 `jw_admin`  
6. `jw_admin` 可指派全部并看全校迎检  
7. 角色变更进 `audit_log`
